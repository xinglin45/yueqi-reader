# ADR-0004：中文检索以字面精确匹配为基线

日期：2026-10-19。状态：前置选型完成；MAC-10索引产品功能未实现，MAC-03尚未建库。

## 选择

本书/书库检索以原文中的字面子串为语义基线：少于3个Unicode标量的查询采用有界、可取消的子串扫描；3个及以上字符在运行时支持时可使用FTS5 trigram候选，再按原文精确核对。结果必须限制批量/分页、绑定书籍及修订；索引失效允许退回原文扫描，不能阻断阅读。SQL输入参数化，%/_/引号/FTS运算符都按用户原意处理，不能直接拼成MATCH表达式或LIKE通配符。

原因来自实际样本：[Python SQLite结果](../verifications/mac-06/search.json)、[macOS系统SQLite结果](../verifications/mac-06/search-native-sqlite.json)。两个真实运行时分别为3.53.4与3.54.0，均有unicode61/trigram。Python11项、系统9项字面基线核对通过；最终Flutter SQLite绑定/版本尚未选择，MAC-03必须对实际链接库复验能力。

| 查询 | unicode61观测 | trigram观测 | 方案 |
|---|---|---|---|
| 山 / 山间 | 中文连续文本里词内查询漏掉 | 不足3字符全文查询无命中 | 参数化instr/分段扫描 |
| 山间来信 / 山間來信 | 连续文本中的子串可能漏掉 | 得到预期候选 | trigram＋原文核验 |
| 📖 / 标点 | 不能依赖词token得到字面命中 | 不足3字符 | 原文扫描 |
| e＋组合音标 / é | 本批不统一规范化 | 短查询仍需回退 | 保留原始编码与偏移 |
| 100%_ / OR "NOT" | 不作为查询语言/通配符 | 明确引用全文表达式后再核验 | 参数绑定和字面语义 |

[SQLite FTS5维护文档](https://www.sqlite.org/fts5.html)明确unicode61按字符类别组成连续token，以及trigram短于3字符的限制。本批没有安装或声称拥有中文分词扩展，不使用porter冒充中文分词，也不引入需要额外维护的自定义tokenizer。

## 测量与边界

本地生成10000段、4268887字节语料，Python SQLite内存/本地文件实验的trigram建索引约0.04秒，数据库含正文/索引约11.8MB；具体时延以JSON原值为准。稀有长词“唯一目标词”在本机热缓存测量中：instr约2.6ms、trigram＋核验约0.01ms量级；频繁短词LIMIT50返回很快，不能据此推断全库长尾。该数据不等于Flutter应用端性能、生产大书或50MB预算已通过。

偏移转换已经举例验证：SQLite instr返回从1起的Unicode标量位置，不能直接当UTF-16传给JS/Dart/原生语音。匹配后在原文块上计算UTF-16范围，与spine/block/修订绑定，覆盖emoji/组合字符。简繁等价检索若后续启用，只能在派生索引/映射层进行，禁止改原文、书籍ID或保存位置。

MAC-10须实现后台批次、取消/迟到事件、增量重建、索引修订与事务、摘录/跳转；查询长度/结果上限与全库分页也需真实验证。本批只交付可复现的研究脚本，没有新增生产数据库、迁移或用户搜索入口。
