# 本地资料升级与恢复

适用：MAC-03存储、MAC-16、MAC-04与MAC-05 / 0.0.7+7，schema v6。当前为内部自用构建；完整用户备份/导入恢复界面在MAC-14实现。本页描述本批已有恢复机制和人工处理边界。

正常启动从系统Application Support内的novel目录打开novel.sqlite，不依赖登录或后端。升级旧schema前，程序生成migration-backups/v版本-时间.sqlite.partial，核验quick_check/版本后才改为.sqlite，并在事务中升级。备份失败则不升级；不完整.partial不能当作可恢复备份。

遇到“只读”提示时，当前版本暂不保存更改。原数据库保留，迁移失败时已经提交的数据不被删掉；若备份创建成功，它仍在migration-backups中。遇到“资料暂时不能打开”时，重试只重新打开，不会删除或重建已有数据。不要用空库替换来消除提示。

人工恢复按以下顺序处理：

1. 退出所有阅栖实例。先完整复制novel资料目录到新位置，包含objects、migration-backups、novel.sqlite及可能存在的-wal/-shm；不要仅在运行中复制主库。原目录保持作为回退副本。
2. 在独立恢复目录中复制一份**已核验的.sqlite迁移快照**作为novel.sqlite，并复制对应objects。迁移快照本身是完整数据库，不把原库的旧-wal/-shm拼到这份快照旁。单独保留原有成套数据库和旁文件。
3. 用兼容该schema的构建在恢复副本中验证quick_check、外键、书架/修订/文件摘要与位置，再决定是否切换到恢复副本。源码工具和自动测试已验证从v1快照恢复后升级到v6；尚无面向用户的恢复选择器，不通过修改系统设置强行接管目录。
4. 确认副本可用后再安排目录切换；保留原副本直到人工确认。应用不会自动覆盖原库。未来版本库应先使用对应的新版本，不尝试由旧版本降级。

当前程序可报告孤儿文件与缺失引用，不自动回收。物理磁盘损坏、真正断电/满盘、系统备份恢复及整套迁移UI尚未验收；逻辑事务回滚和进程退出恢复不代表这些情况已保证。

MAC-16：书库备份仅限novel目录；不得带入兄弟目录novel-device或访问状态字段。导入的访问字段被拒绝，新书库重置残留声明；迁移快照不含成年资格。完整备份恢复UI/OS整机镜像恢复仍未验收，界面隐私锁不是磁盘加密。

## MAC-04导入文件恢复

导入中取消或失败不会创建完成记录；已完成的批次项保留。重启在持有写入租约后清除import-stage。托管卡片“查看文件状态”校验objects摘要，缺失/损坏时重新导入内容相同的原件可修复，并保留已有书籍ID、标题、分级与位置。不要以同名但不同内容代替原件。

引用卡片从本机只读安全范围书签恢复；原件移动可能由系统书签跟踪，授权失效或丢失时选择“重新关联相同原件”。只接受旧摘要一致的文件，内容已改请作为新文件导入。引用不提供原件被删除后的离线保证，未申请全磁盘权限。书签不进入可移植书库备份/同步；MAC-14仍待实现。当前“文件已入库”不代表已生成TXT目录或EPUB阅读器。

## MAC-05目录/索引恢复

重建先预览再确认，失败/取消保留旧活动目录与位置；重试从原件开头构建，不从损坏的部分索引续写。重启清理txt-stage未提交候选，不删已提交版本。索引缺失/摘要坏可打开分章规则重新预览确认，原件摘要不一致须回到文件状态重新关联/导入，不能用旧索引掩盖原件丢失。

分章确认产生新解析修订；旧位置仍绑定旧版本，UI提示保留，由用户选择章节后主动记住新位置。真实磁盘故障/断电不属于本批保证；索引移动与SQL之间崩溃可能留未引用目录，当前不自动回收历史索引。完整书库/索引清理和备份UI在后续任务实施。

## MAC-07 EPUB会话恢复

EPUB使用原始导入、不可变epub-v1解析documents/chapters与既有positions，schema仍为6。每次打开重新核对原件/授权、构造并校验临时资源；同修订结构锚点精确匹配才恢复选区/可见位置。新修订或摘录不匹配保留旧位置并提示，不能把空正文当恢复成功。

epub-sessions是可丢弃派生文件，关闭、取消、失败、锁定时清理；进程异常退出可残留，下一次持有写入租约的启动会清除。未来备份必须排除它。引用模式只保证本次会话快照一致，再次打开仍需要原件；不提供删除原件后的长期离线保证。Web进程退出提供“重新加载本章”，修复授权/重关联后可在文件状态返回重新打开，旧位置始终保留。见[ADR-0010](../decisions/0010-mac07-controlled-epub.md)。
