# macOS 双形态小说阅读器：低存在感阅读功能与 UI/UX 设计规范

> **用途**：交给 Codex，作为 macOS 小说阅读 App 的产品设计、界面设计、交互设计和原型验收参考。  
> **产品定位**：完整的日常小说阅读器 + 可随时切换的低存在感阅读模式。  
> **设计目标**：正常阅读足够好用；碎片时间可立即进入阅读；需要专注工作时可迅速收起，之后无损恢复。  
> **目标平台**：macOS 优先；后续如扩展 Windows、iOS、Android，应保持阅读数据结构和交互语义可复用。  
> **优先级定义**：P0 = 首版必须；P1 = 强烈建议；P2 = 后续增强。

---

## 1. 提供给 Codex 的核心设计指令

请把本产品设计成 **“双形态阅读器”**，不要只给传统书架加一个“隐藏按钮”。

1. **正常模式**：像一款真正优秀的 macOS 小说阅读软件，具有书架、书籍详情、目录、搜索、阅读主题、字体排版、进度管理、设置等完整功能。
2. **低存在感模式**：最少的 UI、极低的视觉占用、快捷切换、不中断工作流程。必须设计菜单栏阅读、悬浮阅读条、极简阅读窗、一键收起与无缝恢复。
3. **两种模式共享同一个阅读会话**：同一本书、同一章、同一段、相同的阅读进度；切换不刷新、不丢进度、不重新找位置。
4. **macOS 原生体验**：优先采用 Apple 风格的简洁设计、合理留白、系统字体、浅色/深色适配、键盘操作、多屏幕适配，而不是网页后台管理系统式 UI。
5. **默认不打扰**：不播放切换音效，不弹出无关通知，不在每次隐藏/恢复时展示动画、广告、欢迎页或提示弹窗。
6. **可控、可恢复、可退出**：低存在感模式是用户主动选择的显示方式；始终保留清晰的设置入口、退出入口与快捷键说明。

**界面设计交付范围**：正常模式、低存在感模式各子形态、菜单栏菜单、快捷键设置、阅读器设置、空状态、异常状态、模式切换流程以及必要的交互原型。

    ├── 多显示器与窗口位置管理
    └── 本地隐私与可选数据同步

## 4. 低存在感模式：核心功能清单

### F01. 一键收起 / 一键恢复（P0，最高优先级）

**目标**：无论用户正在菜单栏、悬浮条还是极简窗口阅读，都能通过统一操作瞬间停止显示阅读内容。

**交互要求**：
- 支持一个用户可自定义的 **全局快捷键**；建议初始候选 `⌥ + ⌘ + R`，必须能检测并提示快捷键冲突。
- 首次按下：收起本 App 的所有阅读窗口、浮层和弹出菜单，保存当前阅读位置。
- 再次按下：恢复**之前的阅读形态、大小、位置、透明度和阅读位置**。
- 收起后不要把阅读器最小化到 Dock 里留下醒目的缩略窗口，也不要展示收起成功的 Toast。
- 收起前若用户正在另一个应用工作，尽量不改变该应用的输入焦点；恢复时也要避免无意义地抢焦点。
- 支持“仅收起悬浮阅读窗口”和“收起所有阅读窗口”两种可配置行为；默认为收起所有阅读窗口。
- 退出、睡眠、重新登录后不应自动弹出低存在感阅读内容；默认由用户主动恢复。

**状态**：显示中 / 已收起 / 正在恢复。要求操作具有幂等性，不出现两个阅读窗口叠加。

### F02. 菜单栏阅读（P0）

- 在 macOS 顶部菜单栏提供简洁图标，可点击弹出小说阅读面板。
- 支持建议尺寸约 `300 × 380 pt`，可由用户调整并记忆。
- 内容包括：当前章节、正文、上一页/下一页、暂停/继续滚动、更多操作；常态只保留正文和最小控件。
- 点击面板外部可自动关闭面板；再次打开从原位置继续。
- 菜单栏图标支持简约/中性样式，可设置是否显示阅读进度，但默认**不在菜单栏显示书名**。
- 弹出菜单同时包含 `打开完整阅读器`、`切换悬浮阅读条`、`快速收起`、`设置`、`退出`。

**设计注意**：菜单栏阅读面板应是 macOS 风格的紧凑阅读工具，不要做成缩小版书架。

### F03. 悬浮阅读条（P0，核心差异化功能）

- 用户可选择显示 `1 / 2 / 3` 行正文，默认 2 行。
- 建议默认尺寸 `420 × 72 pt`；支持自由调整宽度、字号及内边距。
- 支持顶部、底部、左右屏幕边缘定位；可拖动，提供磁吸贴边和位置记忆。
- 内容不显示小说封面、书名、章节标题；可在鼠标悬停后以淡化形式显示控制按钮。
- 支持透明度 `20%～100%`，并可分别设置背景透明度和文字透明度，保证可读性。
- 支持 `置顶 / 非置顶` 开关，默认为非强制置顶或按用户首次配置确定。
- 支持 `点击穿透` 开关：穿透开启时不拦截底层应用点击；须设计明确的临时退出穿透方式，避免窗口无法操作。
- 可自动滚动或按段落推进，支持暂停、继续、上一段、下一段。
- 支持手动显示/隐藏和快速收起，关闭阅读条不应关闭整个 App。

**特殊要求**：不同背景上的文字对比度要足够；低透明度不代表文字必须难以阅读。透明度不宜让 UI 控制项完全不可发现。

### F04. 极简阅读窗（P0）

- 无边框或弱边框，默认隐藏标题栏、书名、目录、工具栏。
- 鼠标悬停指定区域时才显示关闭、模式切换、设置等按钮。
- 允许调整窗口宽高、字号、行距、页边距、背景、透明度。
- 鼠标滚轮、触控板滚动、键盘翻页均可操作。
- 支持 `不激活面板` 风格（在 macOS 技术可行情况下），避免阅读时频繁切断其他工作窗口焦点。
- 多次打开同一本书要复用当前会话，而非产生多个重叠窗口。

### F05. 工作风格阅读主题（P1）

这是**视觉主题**，不是修改小说原文，不应向系统伪装为某个企业软件。

建议主题：

| 主题 | UI 表现 | 注意 |
| --- | --- | --- |
| 纯文本 | 近似无装饰的文字块 | 默认推荐 |
| Markdown 文档 | Markdown 编辑器式字体、留白、淡色结构 | 不把正文错误转换成代码 |
| 代码注释 | 等宽字体、轻量行号、注释色系 | 保持正文可读，不改变文义 |
| 终端输出 | 简洁终端式配色和行距 | 不制造虚假的系统操作记录 |
| 轻量日志 | 逐行密集文本、低饱和色 | 行号/辅助标记不进入复制内容 |
| 自定义 | 背景、字体、色彩、行距自由组合 | 支持主题预览和一键还原 |

在不同模式间切换时，主题可独立配置，例如正常模式使用暖纸阅读主题，低存在感模式使用纯文本主题。

### F06. 鼠标离开自动收起（P1）

- 可选开启。鼠标离开窗口后，经过用户设置的延迟再收起：`立即 / 0.5s / 1s / 2s / 5s`。
- 鼠标重新移入原位置时是否恢复，可单独设置，**默认关闭自动恢复**，避免意外暴露阅读内容。
- 必须区分“收起窗口”和“仅隐藏控制栏”，不能让用户误以为关闭了小说。
- 与点击穿透模式兼容，不允许进入无法恢复的状态。

### F07. 自动滚动与段落推进（P1）

- 阅读条和极简窗都支持 `关闭 / 连续滚动 / 定时切换段落`。
- 提供速度滑杆以及 `暂停/继续`，切换模式时保留用户的阅读节奏设置。
- 用户手动拖动进度或翻页后，可配置暂停自动滚动，避免新位置马上跳走。
- 快速收起时必须暂停计时与滚动；恢复后默认仍处于暂停状态，或按用户选项继续。
- 到达章节末尾时，应有是否自动进入下一章的开关。

### F08. 显示与焦点控制（P1）

- 支持“低存在感模式窗口不显示在 Dock / Cmd+Tab 列表”的**可选菜单栏专用运行方式**。
- UI 要明确提示：切换应用激活策略可能需要重启应用；该设置影响整个应用生命周期，不能承诺对每个窗口实时无缝生效。
- 保留始终可达的设置、恢复主窗口、退出入口；避免因隐藏 Dock 导致用户找不到 App。
- 允许用户设置 `恢复后是否激活窗口`，悬浮条默认倾向于不抢焦点。

### F09. 快速切回工作应用（P1）

- 在阅读器处于前台时执行“快速收起”，应优先让先前的工作应用继续处于前台，而不是闪回 Finder 或桌面。
- 不要模拟工作软件的功能，也不要自动发送键盘输入到其他 App。
- 若先前应用已退出，正常收起阅读器即可，不需要弹错。

### F10. 多显示器与空间管理（P1）

- 允许给每块显示器保存独立的窗口大小、位置、阅读形态。
- 外接屏断开后，阅读窗应自动回到现存屏幕可见范围，不能遗失在屏幕外。
- 明确设置悬浮窗行为：`跟随当前桌面空间 / 仅当前空间 / 固定指定显示器`，受 macOS 能力限制的选项需有解释。
- 全屏工作应用、Stage Manager、多桌面空间、分辨率变化时均需要实际测试。

### F11. 静默启动与关闭（P1）

- 可选开机启动，但默认仅后台准备，不自动打开含正文的窗口。
- 可选菜单栏驻留；首装时解释状态栏图标用途。
- 关闭阅读窗可选择 `仅关闭窗口 / 保持菜单栏运行 / 退出应用`，设置项必须清晰。
- 启动时恢复的是阅读进度与用户设置，**不是未经许可弹出上一次内容**。

### F12. 专注/演示前收起（P1）

- 提供显眼但简短的 `收起所有阅读内容` 菜单项，可与一键收起复用。
- 支持用户主动进入“演示中”状态，在此状态不自动弹出正文、禁用鼠标移入自动恢复，并暂停自动滚动。
- 可提供可配置的提醒（如启动屏幕共享前主动检查），但不应承诺能可靠识别所有会议软件和录屏工具。
- **边界**：窗口隐藏不等于能规避公司设备管理、已发生的截图、录屏或访问日志。不要在产品说明中承诺“完全不可检测”。

### F13. 断点续读与模式同步（P0）

- 统一按 `书籍 ID + 章节/内容定位 + 段落偏移` 保存阅读状态。
- 正常模式、菜单栏、悬浮条、极简窗共享进度，默认同一时间只有一个主阅读游标。
- 隐藏、切换、关闭、睡眠、崩溃恢复时尽可能保存进度。
- TXT 重新导入或 EPUB 内容变化时，定位失败需要有合理回退策略和可解释的提示。
- 不同字号/窗口尺寸改变后尽量定位到同一段落，而不是简单使用旧滚动像素值。

### F14. 极简交互与手势（P2）

- 可选支持触控板轻扫翻页、滚轮按段推进、双击暂停。
- 用户可关闭所有手势，避免在工作软件中误触。
- 低存在感模式默认少动效、无过度弹窗；支持 macOS 减少动态效果设置。

### F15. 场景预设（P2）

建议三个可编辑预设，一键切换窗口配置，不改变书籍进度：

- `碎片阅读`：菜单栏弹窗、无自动滚动、普通字体。
- `角落阅读`：两行悬浮条、低饱和背景、贴边、手动翻段。
- `轻量阅读`：极简窗、纯文本主题、可调整透明度。

不要让预设取代用户独立调整各项参数的能力。

## 5. 快捷键系统（设计默认值，可修改）

| 作用域 | 建议组合 | 操作 | 说明 |
| --- | --- | --- | --- |
| 全局 | `⌥⌘R` | 快速收起 / 恢复 | P0；首次使用检测冲突，支持自定义 |
| 全局（可选） | `⌥⌘M` | 正常 / 低存在感模式切换 | P1；可关闭全局监听 |
| 阅读窗口内 | `← / →` | 上页 / 下页 | 与输入框焦点冲突时不触发 |
| 阅读窗口内 | `↑ / ↓` | 上移 / 下移或上一段 / 下一段 | 由阅读布局定义 |
| 阅读窗口内 | `Space` | 暂停 / 继续自动滚动 | 只在阅读区域获得焦点时生效 |
| 阅读窗口内 | `Esc` | 关闭弹层或收起阅读窗 | 优先关闭菜单，再收起窗口 |
| 阅读窗口内 | `⌘F` | 当前书籍搜索 | 正常模式优先支持 |
| 阅读窗口内 | `⌘,` | 设置 | 与 macOS 约定一致 |

**要求**：全局快捷键数量应尽可能少。除“快速收起”外，其他快捷键默认优先绑定到阅读器窗口内，防止干扰 IDE、终端、浏览器和办公软件。显示快捷键冲突、无法注册和权限不可用时的可理解反馈。

## 6. 必须设计的关键用户流程

### 流程 A：正常模式转入低存在感模式

1. 用户打开书架，选择小说，进入标准正文阅读页。
2. 点击右上角 `低存在感模式` 入口或使用快捷键。
3. 第一次使用时展示轻量配置面板，选择菜单栏 / 阅读条 / 极简窗；之后使用上次选择。
4. 正常阅读主窗口根据偏好收起，低存在感窗口从**当前阅读段落**出现。
5. 不显示新手引导挡住正文；后续可在设置中调整。

### 流程 B：正在阅读时快速收起

1. 用户阅读悬浮条。
2. 按全局快捷键。
3. 阅读条和其他正文表面立即收起，进度保存，滚动暂停。
4. 当前工作应用继续使用，不出现额外弹窗。
5. 再按快捷键，恢复先前阅读形态与段落；恢复后的焦点行为遵从设置。

### 流程 C：从菜单栏临时读几段

1. 用户点击菜单栏图标。
2. 阅读面板显示最近在读书籍当前段落。
3. 通过鼠标滚动或按钮阅读。
4. 点击面板以外区域，面板收起并保存进度。
5. 下一次弹出时连续阅读。

### 流程 D：低存在感返回正常模式

1. 用户从菜单栏或阅读窗口操作 `打开完整阅读器`。
2. 完整阅读器直接进入当前小说、当前章节、当前段落。
3. 不重复生成另一个阅读会话；切换后按设置关闭或保留悬浮条（默认关闭，避免正文重复出现）。

### 流程 E：从屏幕共享 / 演示状态返回

1. 用户主动开启 `演示中`，收起阅读正文。
2. 此状态下不因鼠标悬停或重启自动恢复小说内容。
3. 用户主动退出演示状态，使用快捷键恢复阅读。

## 7. 视觉与布局规范

### 7.1 整体风格

- 偏向 macOS 原生应用：简洁、克制、系统字体、清晰层级、舒适留白。
- 默认遵循系统明暗主题；正常阅读和低存在感模式可独立设置主题。
- 动效尽可能短且可关闭；**快速收起必须优先即时响应**，不能为动画牺牲速度。
- 不使用夸张的玻璃拟态、大面积渐变、强对比霓虹、炫目的悬浮按钮。
- 主操作可被发现，非必要控件仅在悬停、聚焦或菜单操作时展示。

### 7.2 建议的主要页面

| 页面/视图 | 核心元素 | 视觉要求 |
| --- | --- | --- |
| 书架首页 | 导航、书籍卡片、最近阅读、导入按钮 | 适合长期使用，清爽而非密集后台表格 |
| 标准阅读页 | 正文、进度、目录入口、主题/字体调节 | 正文绝对优先，辅助控件尽量弱化 |
| 菜单栏阅读面板 | 章节、正文、微型控制栏 | 小尺寸可读，控制数量受约束 |
| 悬浮阅读条 | 1～3 行文字，悬停控制区 | 默认不显示书名/封面/大标题 |
| 极简阅读窗 | 正文、悬停式控制 | 无边框、无额外装饰 |
| 低存在感设置 | 模式、窗口、透明度、行为、预览 | 即时预览 + 重置默认值 |
| 快捷键设置 | 按键录制、冲突提示、恢复默认 | 清楚标记全局或仅应用内 |
| 菜单栏菜单 | 最近在读、模式切换、收起、设置、退出 | 即使 Dock 隐藏也可完成必要操作 |

### 7.3 建议的尺寸与可调项

这些尺寸只是**原型起点**，不是硬编码限制：

- 菜单栏阅读面板：初始 `300 × 380 pt`，随内容和显示器安全区域调整。
- 悬浮阅读条：初始 `420 × 72 pt`，可切换 1～3 行；在小尺寸显示器上自动约束边界。
- 极简阅读窗：初始 `420 × 280 pt`，允许调整。
- 字号：建议初始 `14 pt`，范围可在 `10～26 pt` 之间配置，扩大范围须保证可用。
- 透明度：`20%～100%`，但必须提供恢复可读性的入口和默认值按钮。
- 支持 Retina、缩放分辨率、系统放大文本、深色模式、多显示器等。

### 7.4 文字排版

- 中文小说重视段首缩进、自然换行、章节标题和段间距。
- TXT 自动识别章节失败时允许手动重新解析。
- 不让章节导航、广告、进度数字频繁占用悬浮阅读条的可见面积。
- 对长段落、特殊符号、英文混排、竖排格式暂不强求首版支持，但要避免溢出、裁切和乱码。

## 8. 关键状态与异常处理

| 场景 | 设计要求 |
| --- | --- |
| 第一次启动，没有书 | 提供明确的“导入 TXT/EPUB”入口和演示占位内容，不强制注册 |
| 未授予必要系统权限 | 解释受影响的功能，支持重新尝试；不应让整个阅读器不可用 |
| 全局快捷键冲突 | 说明冲突或注册失败，提供更换快捷键入口 |
| 快速连续按快捷键 | 不允许窗口闪烁、多开或进度回退 |
| 悬浮窗处于点击穿透 | 提供菜单栏和全局快捷键恢复操作控制的方式 |
| 外接显示器断开 | 自动回收至当前有效显示区域 |
| 切换字体/窗口尺寸 | 保留章节和段落定位，避免跳到章节开头 |
| 小说文件被移动/删除 | 提示重新定位文件，保留阅读记录 |
| 小说内容很大 | 大文件分段加载，不阻塞显示与快捷收起 |
| 系统睡眠后唤醒 | 不主动弹出正文，避免焦点与窗口意外改变 |
| 菜单栏图标被系统隐藏 | 设置或主窗口仍可访问，有明确恢复路径 |
| 辅助功能/减少动态效果 | 可使用键盘导航、可关闭动效，控制对比度和可点击范围 |

## 9. 隐私、安全与系统边界

- 书籍内容、阅读进度优先本地存储；无需账号即可正常阅读。
- 默认不把书名、正文或阅读时长写入系统通知文案。
- 不收集其他 App 的输入内容，也不模拟用户在工作软件中操作。
- 不把“收起阅读窗口”描述为“能逃避监控/录屏/审计”；应用无法保证消除已经产生的系统或企业管理记录。
- 全局快捷键、自动启动、置顶、鼠标穿透等系统相关能力有失败回退和说明；不要求为了单项增强功能授予与功能无关的权限。
- 业务设计遵守组织设备使用政策与正版内容授权要求。

## 10. 建议实现边界（给 Codex 的技术提示，不是强制选型）

如果实现原生 macOS App，可考虑：

- **SwiftUI**：书架、标准阅读页、设置页面和视图状态。
- **AppKit / NSPanel**：菜单栏相关窗口、悬浮面板、特殊窗口焦点与样式。
- **NSStatusItem / MenuBarExtra**：菜单栏入口。
- **全局快捷键注册机制**：优先正规系统 API 或可靠库，提供冲突反馈和注销机制。
- **持久化**：SQLite / SwiftData 等，用于书籍元信息、进度和用户配置。
- **阅读定位**：优先使用章节 + 稳定段落锚点 + 字符偏移，不要只依赖像素滚动距离。

**重要**：`LSUIElement`、应用激活策略、Dock 可见性、全屏空间行为与菜单栏面板的约束应通过 macOS 真机验证；不要仅凭视觉原型就宣称实现完全可靠。若项目已有技术栈，优先与已有架构兼容，不因本文件强制重构。

## 11. MVP 排期与功能优先级

### P0：第一阶段必须完成

1. 正常模式：书架、TXT/EPUB 导入、阅读页、目录、基础主题和排版。
2. 统一进度：正常模式与低存在感模式同步定位。
3. 一键收起/恢复：快捷键、窗口状态、滚动状态和当前段落完整保存。
4. 菜单栏阅读：小型正文面板及必要导航。
5. 悬浮阅读条：1～3 行、拖动位置、尺寸、透明度、基本控制。
6. 极简阅读窗：无边框、弱化控件、可恢复完整阅读器。
7. 设置页面：低存在感模式配置和快捷键管理。

### P1：第二阶段体验增强

工作风格主题、自动隐藏、自动滚动、置顶/点击穿透、多显示器、Dock 模式选项、演示状态、常用预设雏形。

### P2：第三阶段增强

手势、自定义预设、在线合法书源、跨端同步、更完善的书籍管理与阅读统计。

**优先打磨顺序**：一键收起/恢复 → 统一阅读进度 → 悬浮阅读条 → 菜单栏阅读 → 极简窗 → 其他增强。任何花哨效果不得牺牲这条主链路的可靠性。

## 12. 原型、设计稿与验收清单

### 12.1 Codex 设计稿至少需要展示

- [ ] 正常模式书架首页（浅色、深色）
- [ ] 正常模式完整阅读页（展开目录、调整字体设置状态）
- [ ] 菜单栏阅读面板（默认、悬停显示控制）
- [ ] 悬浮阅读条（1 行、2 行、3 行，以及透明背景效果）
- [ ] 极简阅读窗（默认、悬停显示控制）
- [ ] 低存在感模式设置页（可视化预览）
- [ ] 快捷键设置页（快捷键冲突状态）
- [ ] 菜单栏菜单（显示、隐藏、恢复、退出入口）
- [ ] 状态示意：正常阅读 → 低存在感阅读 → 快速收起 → 恢复 → 正常阅读
- [ ] 没有小说、导入失败、文件丢失、权限不足等关键空/错状态

### 12.2 功能验收标准

- [ ] 两种模式读同一本书时能精确延续当前章节/段落。
- [ ] 连续快速按收起/恢复快捷键，窗口不会重复生成或卡死。
- [ ] 收起期间不继续推进自动滚动导致进度丢失。
- [ ] 低存在感模式不强制显示书籍封面、书名或大面积工具栏。
- [ ] 菜单栏模式不用打开标准阅读窗口也可直接继续阅读。
- [ ] 悬浮阅读条尺寸、位置、行数和透明度可控，重启后保留设置。
- [ ] 关闭窗口或切换应用不导致阅读记录丢失。
- [ ] 快捷键冲突、权限被拒、外接显示器断开都有可理解的回退方案。
- [ ] 菜单栏专用模式仍能打开设置与退出应用。
- [ ] 字体、颜色、透明度调整后仍有基本可读性和键盘可达性。
- [ ] 所有增强功能都能关闭，不强制用户使用自动隐藏或点击穿透。

### 12.3 可交付给 Codex 的工作要求

请 Codex 在设计 UI 时：

1. **先设计信息架构和关键用户流程**，明确两个模式与三种低存在感阅读形态的关系。
2. **分别输出正常模式与低存在感模式的主要页面**，不要把“摸鱼功能”堆成单一设置表单。
3. **做可交互的模式切换原型**，至少能演示：书架打开一本书 → 切换阅读条 → 收起 → 恢复 → 返回完整阅读页。
4. **统一设计系统**：颜色、字体、间距、圆角、图标、悬停、快捷键提示、深浅色主题。
5. **设计关键异常状态**，尤其是快捷键冲突、点击穿透、窗口不可见和显示器变化。
6. **明确 macOS 真机验证项**，区分“原型表现”与“系统 API 已实现能力”。
7. 如果实现代码，请优先保持架构解耦：阅读会话/进度状态独立于各显示视图，窗口状态独立于正文解析器。

## 13. 不要做的设计

- ❌ 不要只有传统书架加一个叫“摸鱼模式”的开关。
- ❌ 不要切换阅读模式就从章节开头重新阅读。
- ❌ 不要让悬浮阅读条常驻大标题、封面、宣传文案和密集按钮。
- ❌ 不要让隐藏/恢复依赖多级菜单或鼠标精准点击。
- ❌ 不要使用难以识别的快捷键，也不要默认抢占常用 IDE 快捷键。
- ❌ 不要强制申请全局辅助功能权限才能阅读本地书籍。
- ❌ 不要让点击穿透导致用户无法找回或关闭窗口。
- ❌ 不要在系统启动、电脑唤醒、会议演示期间意外展示正文。
- ❌ 不要声称隐藏窗口就能消除录屏、审计、访问痕迹。
- ❌ 不要过度设计，让低存在感模式比普通阅读更难使用。

## 14. 一句话产品原则

**“正常时是一款完整、舒适的小说阅读器；碎片时间里是一块安静的阅读空间；需要回到工作时可以立即收起，之后准确接着读。”**
